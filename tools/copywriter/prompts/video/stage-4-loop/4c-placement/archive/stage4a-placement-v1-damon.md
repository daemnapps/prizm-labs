Plan the direct-response transformation. Decide three things and write no
script lines — everything downstream depends on these, and they are cheap
to change now and expensive to change later.

Three rules govern everything below:

**The lane sets the depth.** An asset that is already an ad has structure,
offer logic and objection handling to inherit, so the work is mostly swaps.
An organic asset has none of that, so the work is heavy and the runtime
roughly doubles. A static asset has no sequence, no scenes and no runtime,
so it stops after the opening. A sequential asset carries an awareness
ladder even without motion, so it runs the full transformation and ends in a
sequence rather than a video.

**The product enters where the format already re-engages attention.** Not at
the end by default. Find the beat the source itself builds toward — an
escalation phrase, a payoff, a structural cut, a reveal, the resolution of a
bait or a question.

**Runtime decides how many rungs the asset can carry.** Under about fifteen
seconds an asset carries one. It stops at problem-awareness and earns a
click rather than compressing four rungs into thirteen seconds.

Give me these seven sections.

**1. THE LANE**

Answer with exactly one of these four labels, spelled this way, and nothing
else: **ALREADY AN AD** · **ORGANIC** · **STATIC** · **SEQUENTIAL**. Then one
line of why. Later passes key off this label, so an invented name for it
breaks them.

If it is STATIC, say so and stop here — only the opening pass runs.

**2. PRODUCT PLACEMENT**

The beat where the product enters, quoted from the teardown record, and what
makes it that beat.

If the format has no such beat, say so and stop. Some formats make no
promise and cannot carry a pitch; they are openings that hand off to another
asset. That is a real answer, not a failure.

**3. THE OPENING BEAT**

The asset's first beat, identified by its timestamp from the teardown record,
quoted. This is the beat the opening pass rewrites — not the second line, not
the first line that mentions the product. Name it explicitly so the next pass
cannot guess.

**4. AWARENESS**

Which rung the viewer is on when this asset finds her, which rung it must
reach, and therefore how many rungs it has to carry.

**An upstream `[SLOT: …]` is still empty.** Where the baseline injection
left a slot, the fact behind it does not exist yet — do not describe the
end rung as if it did, and never restate a claim the injection deliberately
slotted out. This holds for every section of your output, not only this
one: a fact that was too uncertain to write into the script is too
uncertain to assert in a plan built on it.

**5. RUNTIME**

Source length, expected final length, and where the added time goes. Say
plainly if the runtime cannot carry the rungs.

**6. THE DEVICE CHECK**

The format's central device — the physical action or gimmick that makes it
work — read against the objection bank.

A device can contradict a brand as hard as a sentence can, and it will not
show up as a claim. Destroying a product on camera in front of a customer
whose live objection is that she does not get enough of it is a device
problem, not a copy problem. Name any collision, and say whether the format
survives without the device.

**7. THE RISK**

The one thing most likely to go wrong in this specific asset. A weak
placement beat, a runtime too short for the climb, a format with nothing to
build toward.

Write no script lines. The next pass does that.
