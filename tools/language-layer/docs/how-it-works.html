The language system · brand-agnostic · product-agnostic

How Language Works

Everything a customer or prospect says, from any source, is taken in, labelled, given an ID and stored once. Every tool then reads it from that one place.

Why it exists

To make the business better. Every line is there to improve something:

1How it flows

Words come in on the left and get labelled on the way in. They're stored in the bank, and every tool on the right asks for the lines it needs. Anything an asset uses gets marked as used, so the next asset starts from fresh words.

2The actual chain, step by step

A real run from 2026-09-29: @brand-b TikTok post #1 into the bank. Every step shows the exact code, whether a model is used, and what came out.

Going in · words → bank

  1. 1
    Startno model

    Someone types the command with the brand, avatar and post link. Settings come from the research settings file: up to 400 comments per post.

    research-gatherer/comments.py:102 · ownvoice.py:46
  2. 2
    Pull from Apifyno model

    The TikTok, Instagram or Facebook comment scraper runs on the post. The key is read by name (APIFY_TOKEN), with a spare if the first is spent.

    → 400 comments pulled
    comments.py:52 · components/apify/apify.py:91
  3. 3
    Cleanno model

    Each comment is cleaned: emails, phone numbers, addresses, order numbers and @handles removed. It gets a link to the exact comment, the date it was said, and a source ID.

    comments.py:32 · annotate.py:98
  4. 4
    Skip what's already in the bankno model

    Any comment whose link is already in the bank is skipped.

    → post #2: 394 new (6 already in)
    comments.py:127 · annotate.py:321
  5. 5
    Intake readmodel

    The model reads comments 30 at a time against the avatar's rules and decides: keep or drop (and why), what the words do, topics, sub-avatar, and ad use.

    → kept 338 · dropped 62 (52 too short, 10 other)
    annotate.py:186 · prompts/annotate-row.md · claude-sonnet-5
  6. 6
    Labellermodel

    The model reads the kept lines 20 at a time and gives each an awareness level, a sophistication signal and the lane the words point to. If a reply breaks, it splits the batch and asks again. Origin (internal/external) and voice are set by rule, not by the model.

    → awareness: product 130 · unaware 97 · unclear 52 · most 40 · solution 16 · problem 3
    language-layer/tools/label.py:186 · prompts/label-awareness-v2.md · label.py:55
  7. 7
    Pick the laneno model

    If the person has ordered, they're a customer, or churned if they cancelled or refunded. Otherwise the words decide: customer, lead or prospect.

    → prospect 270 · lead 60 · customer 8
    annotate.py:261
  8. 8
    Build the lineno model

    Names are replaced with [name], and source, signal (likes), topics, use and labels are attached.

    annotate.py:278
  9. 9
    Give it an ID and file itno model

    Next number after the highest ID in the avatar's folder: language_<brand>_<avatar>_<lane>_NNNN. Written to prospects.json, leads.json or customers/.

    → 338 lines filed
    annotate.py:401 · :337 · :363
  10. 10
    Run recordno model

    Filed, dropped and held lists, a report, and a page that shows the intake prompt word for word.

    comments.py:139 → runs/research/<brand>/comments-<time>/
  11. 11
    Save to the repono model

    A session commits and pushes. The gatherer doesn't commit by itself.

    → commit 497b7c89c · 611 lines
    (by hand today)

Other ways in, same steps 5–9: ownvoice pulls Meta ad comments (warehouse, then Apify on the top 15 ads) and Gorgias tickets (warehouse), from the last run onward. On 2026-09-28: Brand B 212 filed, Brand A 167 filed. deep runs Reddit questions per sub-avatar and goes through the labeller only, with no intake read.

Coming out · bank → ad

  1. 1
    The prompt asksno model

    A stage prompt holds a slot like ?hooks. The chain fills in the run's avatar and lane, and for a result-first hook it switches to the result tags.

    video-teardown/machine/chain.py:842
  2. 2
    The chain's own mapno model

    This chain's list of tags per stage, e.g. hooks = hook, problem-language, transformation-reaction… Then it hands off to the shared engine.

    video-teardown/machine/language.py:38
  3. 3
    The engine searchesno model

    Loads every line for the avatar and skips retired lines and lines already used. Identical lines collapse into one with a "said N×" count. Filters by lane and awareness, then ranks: labelled first, then tag order, topic, then loudness.

    → 40 lines per stage
    language-layer/language_layer/engine.py:383 · :274
  4. 4
    Widen if thinno model

    If fewer than 8 lines match, it relaxes topics, then lane, then both, and says so in the header.

    engine.py:402
  5. 5
    Hand to the modelno model

    Each line is shown as [id] "exact words" with speaker, tags, source, date and likes. The stage writes with them and lists the IDs it used.

    engine.py:351
  6. 6
    Mark as usedno model

    After the brief is done, the IDs it cited or quoted are written to the used lane, so the next asset gets fresh words. Bank lines are never edited.

    video-teardown/machine/mark_used.py:122 → language/used/<run>.json

Cleaning up lines already in the bank (labelling, renaming, linking sources): the tool writes a proposal, and the gatherer's apply step writes it in. Same one door as new lines.

Copywriter: steps 1–5 are the same, through its own map. It doesn't filter by awareness or used, and it doesn't mark lines used yet.

10Plugging in a source: Gorgias

Gorgias is already wired in. This is how any new source joins.

Brand A on · 218 ticket lines in the bankBrand B off · its own Gorgias account isn't in the warehouse yet
  1. Where it's read from: the company data warehouse, which already holds every Gorgias ticket message. The same data feeds CS metrics.
  2. How a brand turns it on: its Gorgias account is synced into the warehouse, and its settings file (brands/<brand>/operations/brand.json) names "helpdesk": "gorgias". After that, the daily run pulls every ticket message since the last run. Today the warehouse holds Brand A's account only; Brand B runs a separate one.
  3. What happens to each message: signatures, addresses and names are stripped, then it's labelled (lane, awareness, origin = internal) and filed with a source ID ticket_<brand>_gorgias that links back to the ticket and message number. Whether the sender has ordered comes along with it.
  4. Where it goes: into the same bank as every other source, so ads, copy, email and CS all see it at once.

Any other source works the same way: a way to pull it, a source ID by the Naming Standard, and the labeller. Nothing downstream changes.
