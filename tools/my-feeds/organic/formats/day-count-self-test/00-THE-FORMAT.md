# Day-count self-test

**15,059,706 views proved it** · 7 of Damon's swipes use this format

## What it is

The runtime is organised by a rising day counter stamped in the identical position over the identical tight framing of the same body area. Nothing changes between beats except the number and the body. Wardrobe changes at each stamp are the proof the days are real and separate.

## Why it works

A date ledger converts a demo into a trial the viewer is auditing. Because the frame is identical every time, the only variable left is the thing being sold, so the change reads as caused rather than claimed.

## The beats, in order

1. Day 1 — the untreated state in the framing that will be repeated, product applied on camera
2. next stamp — same frame, new wardrobe, product applied again
3. next stamp — the first readable change
4. next stamp — the change is now obvious in the same frame
5. final stamp, or the product held up to camera as the answer

## On-screen text

one day or interval stamp per beat in the identical position ('Day 1' → 'Day 14' → 'Day 30' → 'Day 90'); often a pinned POV promise on the opening beat; the stamp is an index, never an argument

## Camera

one repeated framing — a selfie front camera or a fixed high angle — identical distance and angle at every stamp, same room, same light

## Higgsfield — image prompt

```
vertical 9:16, {subject described exactly} in {room}, tight framing on {body area}, {light source}, phone front-camera look, slight grain, no retouching, no on-screen text — regenerate this exact framing for every day stamp, changing only {wardrobe} and the state of {body area}
```

## Higgsfield — motion

```
camera fixed, subject holds still, only the hands applying {product} move; identical framing across every beat (same seed)
```
