# swipe-paid — competitor brands, torn down from their live ad libraries

**swipe-paid** — takes **an advertiser's AdPlexity sweep**, makes **that
advertiser's folder in the pool: its copy blocks (`blocks.json`, `blocks/`),
landing pages (`_pages/`), the raw sweep (`_raw/`) and a teardown page**. Does
not **write our ads**. Triggered by
`python3 components/swipe-paid/build.py cluster <ALL.json> <brand-slug>`, then
`resolve`, `harvest`, `records` and `capture` (only `resolve` spends credits).

One folder per brand, identical shape every time, so any two brands read alike
and diff against each other.

**This is a component, not lab.** It moved out of `the team notes/swipe-paid/` on
the owner's word, 2026-09-22. The header used to say "R&D under `lab/` — nothing
here runs or gets consumed outside `lab/` until it graduates"; that was true
until the move and is false now. `intake/` and both teardowns read this pool as
a matter of course.

## The split

**Words live here. Media lives on Drive.**

| | Path |
|---|---|
| Words — every `.md`, `teardown.html`, `_raw/*.json` | this folder |
| Media — creatives and page captures | `Team Drive/swipe/paid/<brand>/`, reached through `swipe_home.py` |

The Drive tree mirrors this one exactly, per the lab convention in
`lab/CLAUDE.md`. Every `.md` carries a `**Drive:**` line naming its mirrored
folder, so the words always point at their media.

Media never enters git — `.gitignore` blocks the extensions outright. Competitor A
alone is 3.5GB, and every file of it re-downloads from the ad IDs recorded in
its block file.

## Structure — the standard, the same for every brand

```
swipe-paid/
  README.md            the brand index
  _TEMPLATE/           the schemas a brand's judgment files follow

  <brand>/
    _BRAND.md          what they sell, counts, offer, stack
    PROFILE.md         regenerated by profile.py — never hand-edited
    teardown.md        the write-up (hand-written judgment; never machine-overwritten; `build.py brief` refuses while it exists, `--replace` overwrites (SI-84 (paid pool bugs)))
    teardown.html      the one-page picture, built by build_page.py
    teardown-content.json   what the page says that a person had to judge
    blocks.json        every copy block and every ad in it (sweep-stamped)
    pages.json         every captured landing page: type, height, url
    blocks/NN_<slug>.md     one file per copy block
    _pages/<slug>.md        one file per landing page
    _raw/              the advertiser sweep, verbatim
```

Drive mirrors it: `Team Drive/swipe/paid/<brand>/blocks/<slug>/{video,photos}/`
and `_pages/<slug>/page.{png,html,txt}`. The drive folder is `blocks/` for every
brand (it was `angles/` on the older ones until 2026-09-21).

The tools, all here: `build.py` (cluster · resolve · harvest · records · capture ·
db), `refresh.py` (fold a new sweep into an existing brand, never deleting),
`build_page.py` (render `teardown.html`), `md_to_content.py` (lift a hand-written
`teardown.md` into the content json), `profile.py`, `standardize.py` (bring every
brand to this shape; `python3 standardize.py check` prints the matrix).

**Nothing old is ever deleted.** A refresh adds; a superseded page is kept beside
the new one (`teardown-2026-08-19.html`, `_pages/<slug>/2026-08-19/`).

## Block vs angle — the one thing to get right

A **block** is ads that share one paragraph of copy. It is mechanical, a
`GROUP BY`, and it is what `blocks.json` and `blocks/` hold. It says what copy
an advertiser has locked, nothing more.

An **angle** is the read on a problem — signed in the brand's
`strategy/angles.json`, where the rule is "no receipt, no entry". It lives on
`creatives.angle`, put there by a person, and one angle runs across many blocks.

They were the same word until 2026-09-02 and it hid the thing that matters. In
our own account one block held an ad that took $__ and one that took $__
same paragraph — the difference was entirely in the picture. Copy cannot carry
an angle; the frame can, which is what `scan_frames.py` reads.

## Rules

1. **One block = one copy block.** Ads cluster by identical headline + primary
   text. `NN` is rank by creative volume, so `01` is the block carrying the most
   footage — the copy they are betting on. A block is not an angle; see above.
2. **Cluster before you resolve.** The sweep returns copy but no landing page;
   the LP only comes from `/ads/<id>` at 1 credit each. Cluster into blocks
   first, then pull detail for one representative ad per block — 18 credits
   instead of 830.
3. **Pages are captured once.** A page can serve several blocks (on competitor-a,
   four pages carried eleven). It lives once under `_pages/` on both sides; the
   block file names it.
4. **No page means no folder.** If a block has no capturable landing page
   (broken merge tag, dead LP), its block file records why and no Drive
   `page/` folder is created.
5. **Every brand fills `_TEMPLATE/` exactly** — same headings, same order, same
   fields.
6. **Two judgment slots are never machine-written:** *Structural findings* and
   *What to take, and what to beat* in `teardown.md`. Everything else in the
   file is countable and comes straight from the data.

## The four questions

Answered 2026-09-23, when this folder owed them as a resident
(`components/CLAUDE.md`).

- **Engine + owner:** `build.py` (sweep → blocks → angles → resolve →
  records → capture), `capture/` (the vendored AdPlexity client with its own
  `market.db` and ad cache), `standardize.py` (brings every brand folder to
  the one shape, and never deletes or rewrites a hand-written teardown),
  `own/ingest.py` (our own ads, out of the Supabase tables),
  `scan_frames.py`, `corpus.py`, `serve.py` (the board, port 8780).
  **the owner.**
- **Definitions + curator:** the folder shape itself is the contract —
  `<advertiser>/blocks.json`, `_pages/`, `_raw/`, `judgements.json`,
  `frames.json`. **the owner.** A brand added by hand gets the same shape or it is
  not in the pool.
- **The plane it emits:** none per invocation — this is a **POOL**, read by
  `intake/` and both teardowns, not a run-per-call machine. Its record is the
  folder. Media and page captures mirror to
  `Team Drive/swipe/paid/<brand>/`, named in a `**Drive:**`
  line on every `.md` so words always point at their media. Records written
  before 2026-10-07 still name `the shared drive/swipe-paid/…`;
  `swipe_home.resolve()` reads that form, so they keep working.
- **Records (O12 (records adapter)):** none: no runs by design — a pool whose record is its folder (the developer, 2026-10-07, triage page 7).
- **Manifest per entry:** `<advertiser>/blocks.json` — every angle, the copy
  on it, how many creatives sit on it, where the traffic goes. Derived files
  (`swipe.db`, `own/*/ads.json`, `.build/`) are gitignored and rebuilt,
  never migrated.

**Read surface — who may read what** (the developer, 2026-10-07, triage action 6 (declare public surfaces), provisionally on the owner's behalf — he sees it in the decision log and may strike any line). Besides `<advertiser>/blocks.json`, `_pages/`, `_raw/`, `judgements.json` and `frames.json` above, other components may read these by path:
1. **`<advertiser>/blocks/<block file>`** — one block, with its `**Landing page:**` line (image-teardown, naming); **`<advertiser>/pages.json`** (intake); **`<advertiser>/_BRAND.md`** (swipe-organic's export).
2. **`<brand>/angles/*.md`** (image-teardown, copywriter's library).
3. **`own/<account-id>/`** — the folder names are our ad-account ids (swipe-organic's public export scrubs them); **`own/<account-id>/ads.json`**, the rebuilt cache, read by intake and video-teardown. It is gitignored: a reader must treat it as possibly absent.
4. **`README.md`** (video-production's pipeline page).
5. **`swipe_home.py` — the contract surface for BOTH pools** (SI-47 (swipe switch), 2026-10-07). Every swipe reader and writer, paid and organic, finds the pools through it: `root(pool)`, `path(pool, …)`, `label(pool, …)`, `resolve(stored)` and `shared_assets()`. It is the one Python file other components import (swipe-organic, intake, image-teardown, copywriter, ad-variations). It builds on `components/brandpath/drive_index.py` `mount()`. `USE_LAB = True` points it back at the lab folders; since the developer moved the pools on 2026-10-07 those folders no longer exist, so it is no longer a working revert. It moves to the repo-side `swipe/` home with the 2 Nov move.
Nothing else here is imported; everything else — `build.py`, `capture/`, `swipe.db`, `.build/` — is internal and may change without notice. A reshape of any file above is a contract change: say so here, and move the readers in the same commit.

**Where a second person gets the content:** the Drive path above,
`Team Drive/swipe/paid/<brand>/`, reached through `swipe_home.py`.

**Every key travels by name** — the environment, then the macOS Keychain.
`ADPLEXITY_API_KEY`, `SUPABASE_DB_URL` and `GEMINI_API_KEY` were all read
out of files on disk until 2026-09-23; none is now. The AdPlexity client, its
`market.db` and its ad cache moved fully inside this folder the same day —
nothing here reaches into another repo.

  `chain_records.py` is cheap because it did not mint a kind — it files onto an
  existing one and distinguishes itself with a single constant. One shared kind
  behind one adapter is 50–100 lines per component; a kind of its own is
  450–650 plus a manifest plus worker wiring.
