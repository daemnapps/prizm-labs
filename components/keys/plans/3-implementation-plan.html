Every machine gets the same key file, with its own keys. A names-only template in git sets which variables exist. the ops lead and Operator B, both admins on the company accounts, create a key for each person and for the Mac mini, build each machine's file from the template, and send it. When keys change later, they send a replacement file. Anything else on a machine is that person's own setup: a personal file, the Keychain, several files. It isn't checked, and a replacement never touches it. Checks start only when a piece of work enters the system path.

Five steps, each one safe to stop at

1 · ADDThe loader, with the old locations as a fallbackNothing breaks: every current setup still loads.
2 · ISSUEPersonal keys into managed filesOld shared keys still work alongside, so nobody is cut off.
3 · SWITCHReaders move to the loaderThe mini's worker and the owner's one-file helper first; everything else when it next goes through the system path.
4 · REVOKEOld shared keys, on an announced dateOnly after a smoke test on each machine: one cheap call per vendor with its own key, pass or fail by name.
5 · TIDYThe fallback is turned offPer person, once nothing reads the old locations.

What is checked, and when (the developer, 29 Sep)

Not checked: personal setups

  • Where someone keeps their own keys: a personal file, several files, the Keychain, shell exports
  • Trial keys and tools only one person uses
  • No note to anyone. Keys made under a company account show in that vendor's admin console, which the admins check when someone leaves.

Checked: when work enters the system path

  • /system-fit flags keys read by path or from a Keychain, and names missing from the template
  • /system-ready moves those reads to the loader and has company keys issued for whoever runs the work
  • /system-review does the same for components already in the workspace when they're next reviewed

Always on, whatever the setup:

  • The walls: no key in git, in chat, or read by path in code that enters the system.
  • The mini loads only its managed file.
  • Revocation dates. When an old shared or leaked key stops working on its announced date, anything still using it stops too, however it was loaded. That date, backed by the smoke test, is the only thing that pushes a switch.
