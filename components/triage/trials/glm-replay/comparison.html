Recommendation

  1. Keep every triage write-up on Opus: issue summaries, action summaries and decision options. Two independent blind tests now agree that GLM's factual error rate on our code is several times Opus's. Confidence: high. Reverse if a newer GLM model is replayed on the same 10 briefs and makes no more errors than Opus.
  2. Drafts are worth one narrower trial, not a move. GLM writes a good diff when the decision to draft is already made. Split the job: Opus decides draft-or-decline and writes the reason; GLM writes the diff only for items marked "draft"; every diff must apply and pass its test before anyone sees it. Rerun on the next round's drafts and move GLM to diff-writing only if it matches Opus there. Confidence: medium, because 6 shared diffs is a small sample.

How it was run

  • Whole jobs, rerun exactly. Each replay used the original request's instruction verbatim, at its original base commit (0fabb40eb, e6d8103826), in an isolated copy that cannot see later commits. Branches sit under replay/glm/ and are never merged.
  • Same tools as Opus had. Both ran under the worker's ordinary maker permissions, so the permission flags were identical.
  • Sample fixed in advance. The 10 briefs were picked by seed 20261002 (one per component, at least one P3) before any GLM output existed.
  • Blind judge. One independent Opus reviewer saw each pair as A and B in random order; the key was kept apart. GLM's commit name was swapped for the base's so it couldn't give the writer away. The judge checked claims only at the base commit and test-applied every diff in its own copy.
  • Judge bias guard. The deciding measure is cited, checkable errors, not preference. The stream re-checked two GLM errors itself.
  • Not available. No triage-owner acts exist yet in the decision log to score against.
  • One judge side effect. While cleaning up, the drafts judge pruned one stale worktree record in the shared repo. The record belonged to another session, its folder was already gone, and no files changed.
