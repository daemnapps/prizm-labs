# Presets
80 one-shot slash recipes (45 stills such as /hero-shot, 18 product-effect videos such as /paint-wave, 17 person-effect videos such as /abandoned-carnival): a supplied photo plus a command gives a fixed-prompt result with no questions.
Source: `presets/ (80 files)`, `_catalog-presets.md`, `SOURCES.md`

## Inputs it needs
- One supplied image: a product photo (45 image recipes and 18 product-effect videos) or a clear portrait of one person (17 person-effect videos). Never invent a subject.
- The slash command alone is the whole creative brief; no written brief, no questions. Explicit format or count requests override defaults (square 1:1, landscape 16:9, Reel/Story 9:16); default is one output.

## Steps in order
1. Reuse a confirmed media id; otherwise `media_upload_widget` as the only tool in that turn and resume after upload; HTTPS URL via `media_import_url`. Upload each source once.
2. Image recipe: `generate_image` with params, the source as role `image`, the preset's parameters and the master prompt unchanged; `jobs_wait`; return via the generation widget.
3. Person-effect video recipes: `models_explore` get on `gpt_image_2_6_flare` and `seedance_2_5` first; stop before spending if either is unavailable (no silent substitution).
4. Video recipes: `generate_image_batch` index 0 with the Preprocessing master prompt (source as the reference; role image_references for person effects, role image for product effects) to make the hidden start frame in its initial state; wait; inspect if viewable; stop on failure.
5. Video recipes: `generate_video` once, the frame as `start_image`, `generate_audio false`, the video master prompt. Person effects: seedance_2_5 omni_reference, one silent 8 s 9:16 1080p. Product effects: seedance_2_0 std, high bitrate, one silent 6 s 3:4 1080p.
6. A timeout or unknown submission outcome never triggers a second submission. The start frame stays internal.
7. Report only real job state; a failure is reported concisely instead of inventing a different preset.

## Prompt blocks, word for word
Presets are fixed: the master prompt is sent unchanged. First the shared run instructions (image and video), then the table of all 80 recipes with the core prompt lines quoted verbatim by script (the first two sentences of each Master prompt after the shared identity boilerplate), then 8 representative master prompts in full.

**Shared run instructions, image recipe** (`presets/hero-shot.md`)
`````
Reuse an already confirmed media ID. Otherwise call `media_upload_widget` for the source image as the only tool in that turn, and resume this same preset after the user uploads. If no image is available, use that upload surface rather than asking for another chat attachment. Do not inspect local upload directories or use shell to read attachments. For a user-supplied HTTPS media URL, call `media_import_url` and use the returned media ID. Upload each source only once.

Call `generate_image` with arguments inside `params`, the source media as role `image`, the generation parameters below, and the master prompt unchanged. Wait for submitted jobs with `jobs_wait` (`timeout_seconds:15`); return the completed image through the generation widget. For multiple independent outputs use the full batch protocol and one `show_generation_by_ids` for the completed set.

Explicit user format/count requests override preset defaults; square means `1:1`, landscape `16:9`, and full-screen Reel or Story `9:16`. Generate one final output unless the user requested more.

Execute the selected recipe without another workflow, a plan, prompt choices, model discovery, or extra confirmation. This explicit preset takes precedence over similarly named thumbnail, product-photography or UGC workflows. Keep production instructions and master prompts out of the assistant's response; describe only the visible effect if asked. Report a failure concisely instead of inventing a different preset.

Preserve explicit `use_unlim` requests according to the full generation tools: opt in only on request and keep the flag on rejection; never silently retry with credits. OpenAI-only free attempts (`use_free_gens`) are unavailable here. If the user requires one, explain the limitation without submitting a paid replacement. Do not change a locked model or settings just to make a free request succeed.
`````

**Shared run instructions, video recipe (identity-effect style)** (`presets/abandoned-carnival.md`)
`````
1. Read `models_explore` with `action:"get"` for `gpt_image_2_6_flare` and `seedance_2_5`
   to verify current portrait/reference support, durations and parameters. Defaults
   below are requested settings, not proof of availability. Stop before spending if
   a model is unavailable or incompatible; do not silently substitute another model.
2. Prepare one hidden scene start frame using `generate_image_batch`, with one
   request at `index:0`. Inside `params` use model `gpt_image_2_6_flare`, `quality:"high"`, `resolution:"2k"`, `count:1`, the final aspect ratio,
   `medias:[{role:"image_references",value:<confirmed source media_id>}]`
   and the preprocessing master prompt below. Preserve the person's identity;
   establish the scene in its initial state, before the described animation events.
3. Wait until the preprocessing job is completed using `jobs_wait` (`timeout_seconds:15`).
   Stop on failure. If accessible, inspect for identity, one coherent subject,
   unobstructed face and the required initial state. Do not claim unperformed visual
   checks or submit a pending/failed image to video.
4. Call `generate_video` once, with arguments inside `params`: the generation
   parameters below, `count:1`, `medias:[{role:"start_image",value:<completed image job_id>}]`
   and the video master prompt below. Use `mode:"omni_reference"` for the supplied
   frame and `generate_audio:false` for silent output. Do not pass a `sound` parameter.
   Do not send the original selfie as another
   start frame, use invented media IDs or apply product-studio preprocessing.
5. A timeout/unknown submission outcome must not trigger a second submission;
   use known job/status or report the uncertainty.
6. Wait for the accepted video job with `jobs_wait`. Keep the auto-updating generation
   widget returned by `generate_video` as the final display; do not create a second
   display unless the user explicitly requests one. The start frame stays internal.

Default is one silent 8-second 9:16 video at 1080p, with audio disabled by
`generate_audio:false`.
Explicit user format/count/duration
requests override defaults only when supported. If duration or orientation changes,
update those literal values in both prompts and proportionally rescale motion
timings, preserving the scene and event order. Otherwise use the prompts unchanged.
Follow credit/tool approval gates;
extra paid attempts need authorization. Keep explicit `use_unlim` choices and never
silently fall back to credits. OpenAI-only `use_free_gens` is unavailable in Full;
explain a requested unsupported free mode before any paid submission.
`````
