Ad Variations

One ad that already worked goes in. Out comes the plan: every element marked keep or test, with the brand's own numbers behind it; one-lever variations, highest impact first; new formats built from parts the brand has already proven; which seconds of the original get reused, what AI makes, what it costs, and what each one must pass. It plans — nothing is generated here.

How it works

Each stage is its own prompt, so each can be read and tightened on its own. Numbers never come from a model: the index counts them, and the machine prices every recipe from the route list.

  1. indexVariable IndexEvery teardown the brand has, countedrule reads + a Sonnet coder per post, cached
  2. 0MeasureThe file's own clock: cuts, loudness, fpsffmpeg — no model, $0
  3. 1Anatomy → elementsThe ad by the second, on nineteen fixed elementsClaude Opus
  4. 2Locks vs leversKeep or test each element, ranked by estimated impactClaude Opus · numbers from the index
  5. 3Variation matrixN variations, one lever each, highest impact firstClaude Opus
  6. 4New formatsProven parts recombined into formats not yet runClaude Opus
  7. 5Merge recipeSeconds reused, what AI makes, route — the machine prices itClaude Opus · $ from routes.json
  8. 6QC gatesThe gates each variation must passClaude Opus · forced gates from routes
  9. 7CongruenceThe static and page section each variation feedsClaude Opus
Input

A finished video teardown of a post (triage, record + verbatim transcript, doctrine read, audience read, replication spec), the post's views and saves, and the brand folder.

Output

variation-plan.json — the plan; no component reads it yet — plus a Markdown copy and this page.

Planning cost

—; the brand's Variable Index costs ≈$__ once for 60 posts and then only codes new posts.

{metrics}

{elements}

{evidence}

the most of what a viewer sees and hears with this ad, their views, and every
variable they differ on. A near-twin that differs on one or two variables is

{siblings}

{brand_rules}

a named public figure), give each part its own row: the layout can be a lock
while the person in it is a lever.

Call it twice when the cuts differ. The brand's corpus is organic posts. A
paid cut plays muted by default, is cropped to 4:5, and has to carry an
offer; an element that is a lock for the organic cut can be a lever for the
paid cut (captions, the end frame, the ask, a subject outside the 4:5 zone).

A call about order, awareness or framing goes under the nearest key
(problem_line, ask_placement, camouflage) with the part named.

- LOCK when the corpus shows the brand's top posts converge on this ad's value
  (tendency lock-leaning) AND no near-twin moved results by changing it, or
  when changing it would break what the replication spec marks load-bearing,
  or when a brand rule fixes it.
- LEVER when the top posts vary on it; when a near-twin differs on it and its
  views differ (quote the twin's rank and views); when this ad's value
  conflicts with the audience read or a brand rule; or when the paid cut

  lock on count alone.

  lever, just not in the first set.
- Nothing in the corpus isolates one variable at a time. The impact rank is
  therefore an ESTIMATE, and says what it weighs: how much of the first three
  seconds the element controls, whether the brand's posts show it moving
  results, and what it costs to test (cost class from the evidence table).
- If a lever needs a ruling before it can move (a real person's likeness, a
  voice clone, a public figure, a claim), name the ruling in `needs_ruling`.
  Do not decide it.

    Hand-made spec: the team notes (page (team page))

    How to run it on any ad

    Say it

    “Run ad variations on <brand> post <post id>.”

    Any post that has been torn down works — a post id, or the name of its teardown run. Add what you want: “twelve variations”, “only paid cuts”, “use the relaunch plan for the page sections”.

    What the session does

    1. Checks the post has a finished teardown (triage, record, doctrine, audience, spec). If it doesn't, it runs the teardown first.
    2. Refreshes the brand's Variable Index — only posts torn down since the last build get coded, so it takes seconds when nothing is new.
    3. Runs a free dry run: every prompt filled, nothing spent, the planning cost estimated.
    4. Runs the seven stages, then adds the run to this page and republishes it — same link.

    What comes back

    • A new set of cards on the Test runs tab: locks and levers, the variations, new formats, costs, gates.
    • variation-plan.json in the run folder — the plan; no component reads it yet.
    • A Markdown copy for the team beside it.

    Where it stops and asks you

    • Anything under “the owner decides” — likeness, voice cloning, public figures, the hero SKU, the offer.
    • A variation marked “Needs a ruling” is planned but never produced until you rule.
