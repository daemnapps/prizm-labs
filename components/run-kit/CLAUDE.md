# run-kit — what every marketing chain shares

**run-kit** — takes a chain's declared steps and prompts, makes the run: a free
dry run, reuse of finished steps, a model per step, every prompt saved as sent,
a `run.json`, output filed under `runs/`. Does not know any brand, tool or
prompt. Triggered by importing it (`from run_kit.stage import Chain`).

**Owner:** the owner (engine). Built 2026-09-20, rollout Step 0b — every part
LIFTED from the runner where it already worked (sources named in each module's
docstring), so fifteen tools stop carrying fifteen copies. Touches nothing of
the developer's; `components/chain-runner` is his and is a different thing.

| Module | Gives a chain |
|---|---|
| `paths` | the repo, a component, a lab tool, a brand folder — found by walking up; `portable(s)` / `local(obj)` — what a record stores for a path (repo-relative or "Shared Assets/…", builder card rule 4) and its read-back, through components/naming/repo_paths.py |
| `prompts` | highest `-vN-` wins, numerically; a field nobody supplied is refused |
| `model` | one `claude -p` caller: tiers, size escalation, clean env, transient-only retry, timeout, a plain usage-limit error |
| `claude_door` | **no account is wired in** (the owner, 2026-10-23: "it should just be able to run regardless of who is working on the code base or what account"): every `claude -p` picks its credential here — the company key (`ANTHROPIC_API_KEY`), then the long-life token (`CLAUDE_CODE_OAUTH_TOKEN`), both by name from the one key file, then whatever login this machine holds, then every other Claude login saved under `~/.claude-accounts/<name>/` (one folder per account, `CLAUDE_CONFIG_DIR`), then **Codex** (the OpenAI login the machine holds, text steps only; the owner, 2026-10-23: "it should just work with whoever's account is in use") — and moves to the next when one runs out. An answer the session hand already wrote for a step is returned first. When all of those are out, the step goes to the Claude session running the chain (`DAEMN_HAND_DIR`), on whatever account that session is signed in to — the owner switches between accounts and that is enough. `model.call`, image-teardown `tools/claude_text.py` and swipe-organic `desklib.ask_model` go through it; every other chain's own `claude -p` call moves onto it as its owner touches it |
| `stage.Chain` | run a step: dry run that spends nothing · reuse by prompt-sha + dependencies · `--rerun-from` · prompt-as-sent · skip-with-reason |
| `record` | `run.json`: the assignment, the model and prompt hash per step |
| `tiers` | **the one model table** (Creative Workflow Standard part 1; the developer, 2026-11-26, "Yes, build it"): `tiers.json` says which model each kind of job runs on (`shared`: reads, checks, designs) and, per chain, the jobs pinned to what that chain asked for on 2026-11-26, plus its lean flag, LD-62 (lean model calls). `tiers.for_chain(name)`, `tiers.model(name, job)`, `tiers.lean(name)`; `"default"` = `claude_flags.model()`, LD-100 (chain model explicit). `model.TIERS` is `tiers.shared()`. On it: marketing-calendar, copywriter (`copywriter` and `copywriter-formats`), session-teardown; email-production is listed but keeps its own copy until after 29 Nov. Every entry `status: draft`. Tests: `python3 test_tiers.py` (TODAY = the 26 Nov snapshot; change it in the same commit as a deliberate model change) |
| `ran` | **what ran, one line per Claude call** (Creative Workflow Standard part 5; the developer, 2026-11-26, "Build it now with switch off", then "Yes, move it down"): recorded in `claude_door.run`, so every call through the door is recorded with no change to its chain — the shared caller and every chain calling the door directly; a chain running its own `claude -p` past the door is not, until it moves onto the door. The line goes to `<run_dir>/what-ran.jsonl` when the caller passed `run_dir=` to `model.call` (every `stage.Chain` step does), else to `runs/what-ran/<person>/<YYYY-MM-DD>.jsonl` with the calling script. It holds the model asked, effort, which door answered (login, company key, Codex, session hand), prompt fingerprint and file name (never the text), seconds, outcome, characters out, caller, person id, and tier/why when known; `model.call` with a runner of its own writes its own line (the door never sees that call). **`RECORD = False` in `ran.py` — the switch ships off**; while off every caller is exactly as before. No environment knob (the EFFORT precedent). One instance shared with the by-path door through `sys.modules["run_kit.ran"]`. Never raises. Turning it off: the prompt in 1.8.1 of the Creative Workflow Standard page. Tests: `python3 test_what_ran.py` |
| `filing` | `runs/<tool>/<brand>/<label>/` and the Drive media folder (the mount found through components/brandpath/drive_index.py mount()) |
| `drive_hand` | a FINISHED file under `runs/` goes to the same path on a Drive home, a pointer stays at the old place so every board and step still finds it, and this Mac's copy is dropped once Drive has uploaded it (a one-shot follower started by the hand itself — no scheduled job; the owner, 2026-11-17, after finished renders filled the Mac). `hand(path, to=None)` / `hand_all(files)`; `readable(path, root)` for a page that serves files (accepts a pointer into a Drive home's `runs/`). Homes are named in `~/.drive-homes.json` on each machine, never in the repo: `upright` (Shared Assets, the default, found through `drive_index.mount()`) plus any other a person adds; `routes` there send a `runs/` folder to a named home; `RUNS_TO_DRIVE=<home>` or `off` for one run. A no-op with no mount (the mini, `DRIVE_MOUNT=off`), for files git tracks, and outside `runs/`; never raises; nothing on a Drive is ever removed. A mount route, the owner's direct instruction — an exception to builder-card rule 4 (keys only), since dropping the Mac copy exists only on the mount. Callers: video-edit `machine/to_drive.py` (every edit road's last act) and meta-upload `to_check` (every filed card, any lane). Tests: `python3 test_drive_hand.py` |
| `pool` | bounded concurrency that stops on a usage limit |
| `learnings` | **the one home of what the chain has learned, any chain, any brand** (2026-10-17; the self-reinforcing loop 2026-11-27): rules in force in `runs/learnings/_all.jsonl` (every brand) and `runs/learnings/<brand>.jsonl`, plus the brand-free seed `learnings/seed.jsonl` (a definitions file that travels with the code, so a fresh copy such as Prizm's starts with what the chain knows; read under the shared store, never twice), each naming its `stations` (writing · copy · image · video · edit), optional `formats`, where it came from (`run`, `file`, `from`) and an optional mechanical `check`. Candidates in `runs/learnings/candidates.jsonl`: captured from what the owner already does, never a form: a script he locks over the chain's (`capture`, called by writing_v2 `lock_owner_script`), a call he overrules (video-teardown `decide.set_verdict` → `harvest`), a take finding (video-studio `drama_lane.py decide`). A candidate goes in force when the same change shows in a second run, or at once when he states it as a rule. A one-off edit to one piece ("X became Y", a moved or cut section, a remade picture, a price or offer change) is never a rule: `add()` files it as a candidate tied to its run (`one_off`), and it never goes in force by recurring; 98 such rows the email line had written straight into force were retired to candidates on 2026-11-27. His own words are kept only in his own node (`OWNER_QUOTES`, else the private repo's `context/learnings-quotes.jsonl` when the machine has it), keyed by learning id, never in this repo. Stations read it through `handed(run_dir, station, brand, fmt=)` (the prompt block + `<run>/learnings-handed.json`) and `findings(text, brand, stations, fmt, field)` (the check before anything reaches him): video-writing every v2 pass + the audit loop (a break goes back to the build), copywriter stage 8 + the copy gate, video-studio drama lane setups + every outgoing request, video-production `clip_gate` (LEARNED), image-production every picture (`picture`/`image` rules, as before). Only real runs under `runs/` are handed anything (`real_run`), so tests and sandboxes are unchanged. Other learning stores point here: video-writing `owner-notes.md` (older notes), meta-upload approval-page digests and model-inputs `lessons.json` (picture rules with their code) stay where they are; video-production `playbook_learn.py` keeps a format's production failures in its playbook. `python3 -m run_kit.learnings in-force|note|capture|harvest|check`. Tests: `python3 test_learnings.py` |

Every other module is public through the table above; nothing whose name starts with `_` is.

**Mini run filer (LD-9 (mini run filer), 2026-10-18):** `mini_run.py` files mini lab runs so nobody hand-writes the request JSON — `list` (every `team/dispatch-grants.json` component row and the args its door takes: lab_door.json, else ACCEPTS, else the script's docstring), `file <component> --brand B [--label L] [--dry-run] [--no-push | --print] [name=value ...]` (as the person `git config user.email` resolves to; writes one `platform/data/records/workflow-requests/<stamp>--<person>--<label>.json`, commits it by pathspec, pushes to main), `status [label]` (the mini-worker's answer on origin/main, or your last 10 runs). Lab-run only; never `scheduled`. Tests: `python3 test_mini_run.py`.
