Working a Brief

You get a folder. Inside it is a photo somebody really posted, our first attempt at copying it, and four or five ready-made prompts. Your job is to run those prompts in Higgsfield and pick the frames that look most like the real photo. Nothing in the folder needs to be written, rewritten or interpreted.

Before anything else

This is a draft of how we'd work — tell me where it's wrong

The whole system is built and running, but none of it has met an actual designer yet. I'd rather change it now than hand you something awkward and have you work around it for six months.

  1. Is the folder enough to start from? Open the worked example below and tell me if anything obvious is missing.
  2. Are the prompts usable as-is, or would you want them structured differently for how Higgsfield actually behaves?
  3. Four or five pictures per brief — is that a sensible batch, or the wrong unit of work?
  4. Where does this get annoying at volume? One brief is fine. Twenty a week is the real test.
  5. What do you need that isn't here? Reference boards, a place to log what the model keeps getting wrong, something else.

This is the whole standard. Left is a real post by a real person. Right is ours. They should be hard to tell apart — same kind of light, same softness, same accidental framing. Ours is not meant to be the better photograph.

What is in the folder

Every brief arrives as one folder on the shared drive, named by its brief number — {{BRIEF_ID}}, p149, and so on. That number is how everything downstream finds your work, so keep it on the files.

bleed · 15%

Every picture is 9:16. That is the only shape that runs in every placement off one file.

The feed crops it to a centred 4:5 — the top 15% and the bottom 15% are thrown away there. So everything that has to be seen lives in the middle: the face, the eye line, the hands, the body part the proof is on, the product, any words.

The outer bands are still real picture — more floor, more wall, more sky. Never empty space, never a solid bar. A letterboxed photo announces itself as an advertisement, which is the one thing these cannot do.

So judge every frame twice. Does it read at 9:16? Then cover the top and bottom 15% — does it still read? A face clipped in the second test is a reject however good the first one looked.

References. Most work orders name one or two Higgsfield Elements — the person, sometimes the product. Attach the same ones to every prompt in that folder. That is what makes the pictures one campaign instead of a set of strangers.

The job, start to finish

Roughly twenty minutes a brief once you have done two.

  1. Look at the swipe first

    Open source.jpg and actually look at it before you generate anything. Notice how soft it is, where the light comes from, how badly it is framed. That is the bar.

  2. Run the control

    Open prompts/00-control.txt, select all, paste, generate four. Change nothing in the text. If a prompt looks wrong, tell us — don't fix it quietly, or the next run makes the same mistake again.

  3. Run the rest

    Same for every other file in prompts/. Each one is the control with exactly one thing changed — a different body part, a different room, a different person. That is deliberate: it is how we learn which change moved the numbers.

  4. Keep one from each set

    Not the prettiest of the four. The one closest to source.jpg that also survives the 4:5 crop test. Those are different pictures, and picking the prettiest is the most common way this goes wrong.

  5. Drop them back in

    Make a finals/ folder inside the brief folder and put your keepers in it, keeping the prompt file's name — 00-control.png, 01-the-chest.png. The names carry through to the ad account, so a renamed file loses its history.

The one that gets broken every time

Match the swipe. Do not improve on it.

The source is a phone photo somebody posted without thinking about it. If your picture is sharper, cleaner, better lit or better composed than the swipe, it is wrong — it starts reading as an advertisement, and the only reason this format works at all is that it doesn't.

Grain, soft focus, a crooked horizon, a blown-out window, a hand half out of frame: those are the point. Keep them.

→

No phone or camera in frame, ever — including in a selfie. The photo is taken from the phone, not of it. This is the single most common defect.

→

If the swipe has words burned into it, ours carries the same words, in the same place, at the same weight, spelled the same. A date in the corner is a date in the corner.

→

No retouching pass afterwards. Skin keeps its texture, its pores, its marks. Smoothing the skin is the fastest way to kill an ad built on someone looking real.

When a prompt won't give you the frame

Re-roll it two or three times first — same prompt, same settings. Generators miss.

If it still won't land, write one line in finals/notes.txt saying which prompt it was and what it keeps doing wrong, then move to the next one. Do not rewrite the prompt. A rewritten prompt can't be compared to anything, and comparing is the entire reason we ship four instead of one.

Same goes for adding your own ideas. If you see a better picture in a brief, say so and we'll add it as a variation with its own prompt — so it gets measured like everything else instead of quietly replacing the thing it was supposed to be tested against.
