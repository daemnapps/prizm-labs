01 · The flow

Seven stages. One unbroken line.

Each stage takes one thing in and hands one thing on. The colour of a card says what kind of thing it holds, before the words do.

07 · Performance

Read it back

What the live ad does is read back against its brief and its swipe. When one lands, the machine makes more like it. When one misses, the prompt that made it is fixed once, and everything after is better.

The line stops in one place, every time: nothing is published, sent, or changed on a store until the owner says go. Everything up to that line runs on its own.

02 · The thread

One number, from the swipe to the live ad.

Every brief gets a number once. Every file made from it carries that number in its name, the hand-off carries it, the ad name carries it, and the live id comes back to sit beside it.

swipe                what was taken, and where from
construct            its structure, the brand stripped out
brief-NNNN           the brief, numbered once
brief-NNNN · asset   every file made from it
<role>-handoff       the folder it left in
live id              what came back — the trace is closed

One record per asset, so anything live can be traced back to the swipe it came from, and any swipe forward to what it earned. That is the whole reason a miss can be fixed at the prompt rather than at the output.

Nothing in the tools names a brand. The brand arrives from its folder when a run starts, so the same chain serves every brand and never has to be explained twice.

04 · The folder

Always the same shape.

Every hand-off is one folder and one instruction file the receiver's own tool can read, explain back, and act on.

How work comes back, today. Each person gets their own Drive folder: Shared Assets/handoffs/<role>/<brand>/<name>/. Open it, read handoff.md, do the job, and put the finished files in returned/, each named <brief id>_asset-NN. The team then runs the take-back, which files it against its brief.
<role>-handoff_<brand>_<date>/
  handoff.md      the instructions
  manifest.json   every id inside, checks passed
  briefs/         one brief per piece
  assets/         what they work from or upload
  references/     swipes, inspiration, the product record
  returned/       their finished work

Before a folder is sent, every product, offer and link inside it is checked against the catalog, every link is opened, and every name is checked against the standard. A folder with an unknown id does not leave.

  1. What this is

    One line: the job, the brand, the batch.

  2. Who it's for

    The role, never a name.

  3. What's inside

    Every brief and asset, by id.

  4. What to do

    The steps, in order.

  5. What must not change

    The product, the words, the offer, the link.

  6. Links

    Each link id with its working address.

  7. Checks before you're done

    What to look at before handing back.

  8. How to send it back

    Into returned/, each file named <brief id>_asset-NN. The team takes it back from there.

05 · Use it

In Higgsfield Supercomputer or Claude Code.

Anyone who makes work with us — clippers, creators, editors, designers — uses Prizm Labs from their own Claude Code or Higgsfield Supercomputer account. The repo is public: open it in your account, point it at a brand, run the tool.

  1. Clone the repo

    In Higgsfield Supercomputer, clone github.com/daemnapps/prizm-labs into your workspace. In Claude Code, open the same repo on your machine.

  2. Point it at a brand folder

    Say which brand you are working on. The brand folder holds the product, the customer and the look; every tool reads it, so a brand is never explained twice.

  3. Run the tool

    Say what you want in plain words: "tear this video down for the brand", "make the scenes for this brief", "edit this kit". The tool does the rest and stops where a person needs to look.

Higgsfield runs everything in its own workspace, so nothing is installed on your computer. Claude Code runs the same tools on your machine. Say "pull for updates" in either and the tools stay current.
